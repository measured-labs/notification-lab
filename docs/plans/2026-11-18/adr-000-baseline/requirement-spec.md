## 0. 요구사항 원문 (인터뷰 기록)

- 원문: 인터뷰 기록 `interview.md`(2026-11-18) 그대로. 순서: payment(02) → ledger(04) → notification(06). 사용자(2026-11-18): "노티피케이션000 도메인 설계하고 좌석 ADR18을 진행해야겠네, 위 작업과 통일작업 끝나면" · "노티피케이션 도메인 설계로 ADR000은 마무리해보려는데 지금 진행중인거쟈?"
- Q/A(interview.md 1~7):
  1. 발송 구조 = 평범: 요청 안에서 동기 발송(트랜잭션 안: 기록 저장 → mock 발송사 호출 → 결과 기록). 큐 · 우선순위 · 속도 제한 · 멱등키 없음.
  2. 재시도 = 즉시 고정 3회(백오프 없음 · Retry-After 무시).
  3. 기능 = 트랜잭셔널 알림 API · 캠페인 발송 API · 발송 이력 조회 · 채널 push · SMS · email.
  4. mock 발송사 = 최소 · 별도 모듈(분당 쿼터 · 429 · 5xx · 지연 · 응답 유실 무작위 주입 · 덤프 API 없음).
  5. 채널 = 모듈 하나 · 채널별 경로 · 쿼터 · 장애 설정(대용량 채널 분리는 그 ADR).
  6. 캠페인 = 채널별 행 · 스레드 풀 병렬(크기 설정 · 속도 제한 없음).
  7. stakes = 중간 · 기반 = payment와 같게(PostgreSQL 16 + JPA + Flyway · repo docs · auto · blind/구현 워커 분리).
  - 설계 선검증(codex medium): 4건 반영 끝(디스패처 블로킹 제출 · 202 접수 스냅샷 · 요청 스레드가 100만 건 제출 안 함 · 쿼터 창 경계).
- 합의 때 확인(메인 제안 — payment · ledger 리뷰에서 배운 것):
  8. 도메인 캡슐화(팩토리 · protected set · 리포지토리 save/find만) · 길이 · 범위 검사를 API와 도메인 둘 다 · 모르는 JSON 필드 400 · 문자열 자리 숫자 · 불리언 400 · 제어 문자 · 짝 없는 서로게이트 400.
  9. 일부러 남긴 약점은 재현 스모크로 실제 모습을 확인한 뒤 숫자로 ADR §9에 적는다(중복 발송 · 429 재시도 증폭 · 캠페인 중 트랜잭셔널 지연 · 커넥션 점유).

## 1. 목표·대상 (필수)

notification-lab에 ADR-000 베이스라인(도메인 Notification · Campaign · Flyway V1 · API 5종 · 캠페인 디스패처 · 즉시 재시도 · mock-provider 하위 모듈)이 들어가고, 로컬에서 정상 경로가 돌며, ADR-000이 채택되고 §9 약점이 재현 수치로 적힌 상태.

## 2. 경계·불변식 (필수)

- 정상 경로: ADR §2.1 ①~⑥ · 트랜잭셔널 요청은 채널 순서대로 행 1개씩 · 재시도 포함 최대 4회 · 발송사 실패는 201 안의 FAILED · 캠페인은 targetCount개 끝나면 COMPLETED.
- 입력 검증 위반 = 400 · 아무것도 저장 · 발송하지 않음. 오류 본문 {code, message} · 5xx 고정 문구.
- 일부러 깨지게 두는 것: 중복 발송 · 즉시 재시도 증폭 · 캠페인 · 트랜잭셔널 자원 경쟁 · 커밋 전 다운 시 기록 없음 · RUNNING 방치.
